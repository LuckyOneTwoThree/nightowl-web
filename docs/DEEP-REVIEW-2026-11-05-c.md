## 一、逐条复算明细

### 1. 首屏两套结论（P0，已确认）

`node tools/audit-hero-sleep.mjs`（关注 ARS · 07:30 起床 · 底线 7h · 120 天）：

```
有 Hero 的夜           42
看完低于底线           38
其中仍是金色 highlight  14   ← 首屏同时出现「今晚焦点」与「可看可不看」
金色且未越线            1
样例 2026-11-07 PL-10-ARS-HUL  index=21.2 ★2 剩 6.5h（差 0.5h）
```

**根因不是 decisionStrip 算错**，是展示层没消费它的结论：
`computeTonight` 用 `pickToday`（星级/指数）定 Hero，`HeroCard` 的档位又只由指数决定，
而「低于底线」是 `decision-strip` 事后算的 —— 三个地方各说各话，没有单一裁决点。

### 2. 混合夜文案（成立，但报告没说清可达性）

`nightHeadline({total:4, pending:1, upcoming:3})` 旧实现返回
「今晚 4 场已结束 · 1 场比分待录」——把 3 场没踢的算成已结束，报告属实。

**但**：`hero === null ⟺ 今晚无可安排场次 ⟹ upcoming === 0`。
也就是说「1 场待录 + 3 场未开赛」这种状态**走不到这个函数**（那时一定有 Hero，渲染的是 Hero 卡）。
所以它不是用户可见缺陷，而是**导出函数的语义缺陷**（手机端与未来调用者都可能踩）。
已修并补测试（见 §三）。

### 3. `planWeek` 非最优（成立，且比报告更严重）

`node tools/audit-plan-optimality.mjs`：

```
扫描 84 个「周 × 预算」组合（前 14 候选暴力），次优 6 个
week5 预算 4.5h：计划 UCL-6-ARS-RMA(11.8) = 118 ｜ 可行更优 PL-15-ARS-BOU(26.5)+UCL-6-VIK-FEY(2.9) = 294
week9 预算 3.5h：计划 PL-20-ARS-BRE(11.8) = 118 ｜ 可行更优 PL-19-MCI-TOT(19.0) = 190
```

**报告没看到的那一半**：这两个例子里的「更优解」**同样是关注球队的场次**（ARS-BOU、ARS-BRE）。
`followedEvs.forEach` 按 `cmpPref`（星级 > 故事线 > 指数）预填充，于是
**名气大的先占预算，指数更高的反而被排除**（ARS-RMA ★3/11.8 挤掉了 ARS-BOU ★2/26.5）。
也就是说：问题不只是「全局最优」，还有「同一优先级内部按名气而非按价值排序」。

## 四、待拍板（按建议顺序）

### A. Hero 与决策条统一（P0，报告判断正确，我同意优先做）

最小可行方案：抽 `decideMatch(match, prefs, ctx)` 返回 `{ verdict, sleep, tier, alternatives }`，
`HeroCard` 用它取代「只看指数定档」。**关键取舍是「越线时允许什么视觉」**：

| 方案 | 做法 | 代价 |
| :-- | :-- | :-- |
| A1 降档 | 越线时 `tier` 强制降为 `standard`（金色仍属 Hero，但文案改「可看，但会透支 0.5h」） | 改动小；金色仍是唯一强调，符合现有强调色纪律 |
| A2 改语义 | 金色保留，但主按钮变次要样式 + 顶部加一行代价 | 需要新的视觉层级，得重跑对比度与布局门禁 |

我倾向 **A1**：不新增强调层级，只让「同一件事只有一句话」。但这会改变 14 个夜的首屏观感，需要你确认。

### B. `planWeek` 最优性

修法有两种：把「关注球队」编进目标函数（价值加权），或做 lexicographic DP（先最大化关注场次数，再最大化价值）。
**注意**：无论哪种，都会改变现有「本周精选」结果（可能不再必保所有主队场次），属于产品行为变更。

### C. 预算口径

三选一：① 文案改成「熬夜档位额度」；② 开账本时预算改用真实 sleep gap；③ 两套都显示。
这是产品定义，不是 bug 修，建议你拍。

### D. L1 续期

建议：把 `build:recs` 接进发版流程（打包前重生成），并在 CI 加一条断言
「未来 N 周 L1 覆盖率 > 0」——不然「断粮」只会被用户发现。
