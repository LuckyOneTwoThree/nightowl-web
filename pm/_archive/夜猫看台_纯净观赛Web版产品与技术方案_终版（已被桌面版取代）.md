## 一、产品定位与核心原则

### 1.1 核心定位
专为熬夜球迷打造的 **桌面端纯净观赛工作台（Owl Match Station）**。

### 1.2 三大第一原则
1. **桌面体验第一**：针对 PC / Mac 宽屏场景深度打磨，不为移动端牺牲桌面端信息密度与操作效率；
2. **看球链路第一**：首要目标是保证点击任何一场比赛，都能稳定、高清、无广告地拉起直播流；
3. **极简无负担**：零登录、零竞猜、零花哨玩法；不引入过重的中间件和复杂的跨端转码服务。

## 三、核心算法大脑（完整继承）

算法完全继承自原项目 `miniprogram/utils/engine.js`，转换为纯前端 ES Module 模块 `src/core/engine.js`。

### 3.1 核心判据三铁律
1. **关注联赛加成**：`leagueBonus` 仅在已选关注联赛 $< 6$ 时给予 $+8$ 分；全选 6 个时不加分；
2. **时间待定 (`tbd`) 排除**：`m.tbd === true` 的场次不可信，不担任今晚之选、不进预算背包；
3. **完赛状态兼容**：`isFinished(m)` 同时兼容 `'done'`（ESPN 抓取源）与 `'ft'`（历史手工数据）。

### 3.2 睡眠成本模型（北京时间）
```javascript
export const SLEEP_TIERS = [
  { tier: 0, label: 'S0', cost: 0.0, zh: '零成本', desc: '白天至 22:30 之前' },
  { tier: 1, label: 'S1', cost: 1.0, zh: '轻度',   desc: '22:30–00:30 开球' },
  { tier: 2, label: 'S2', cost: 2.5, zh: '中度',   desc: '00:30–02:30 黄金修仙档' },
  { tier: 3, label: 'S3', cost: 3.5, zh: '重度',   desc: '02:30–04:00 深夜死线档' },
  { tier: 4, label: 'S4', cost: 4.5, zh: '极限',   desc: '04:00–07:00 黎明折磨档' }
];

export function getSleepTier(timeStr) {
  const [hh, mm] = timeStr.split('T')[1].split(':').map(Number);
  const minutes = hh * 60 + mm;
  if (minutes <= 30) return SLEEP_TIERS[1];           // 00:00-00:30
  if (minutes <= 150) return SLEEP_TIERS[2];          // 00:30-02:30
  if (minutes < 240) return SLEEP_TIERS[3];           // 02:30-04:00
  if (minutes < 420) return SLEEP_TIERS[4];           // 04:00-07:00
  if (minutes <= 22 * 60 + 30) return SLEEP_TIERS[0]; // 白天-22:30
  return SLEEP_TIERS[1];                              // 22:30-24:00
}
```

### 3.3 状态机与提前预热
* **比赛状态**：`sched`（未赛）$\rightarrow$ `soon`（赛前 30 分钟预热）$\rightarrow$ `live`（开球至 120 分钟）$\rightarrow$ `ended_pending`（等待比分）$\rightarrow$ `finished`（完赛）。
* **开赛前 30 分钟**：卡片显示【即将开赛】，前端自动向 Sidecar 预取线路，用户点击瞬间无需等待，秒出画面。

## 四、观赛直播核心工程链路（精炼闭环）

因为将核心平台聚焦在**桌面浏览器（Chrome/Edge/macOS Safari）**，整体工程架构得以大幅简化：

```
                ┌──────────────────────────────────────────────┐
                │          第三方站点 (88看球/JRS/低调看)         │
                └──────────────────────┬───────────────────────┘
                                       │ 1. 抓取比赛房间与线路列表
                                       ▼
                ┌──────────────────────────────────────────────┐
                │        本地 Sidecar 抓取与对齐模块             │
                │        (Matcher: 队名模糊映射与置信度绑定)    │
                └──────────────────────┬───────────────────────┘
                                       │ 2. 注入线路至对应赛程
                                       ▼
                ┌──────────────────────────────────────────────┐
                │           Web 界面卡片点亮【🔴 正在直播】     │
                │           用户点击【立即观看】               │
                └──────────────────────┬───────────────────────┘
                                       │ 3. 请求直播流
                                       ▼
                ┌──────────────────────────────────────────────┐
                │           本地流代理服务 (/api/proxy)         │
                │           • 剥除 Referer 绕开防盗链          │
                │           • M3U8 分片路径全量正则重写        │
                │           • TS 分片流式转发 (pipe)           │
                └──────────────────────┬───────────────────────┘
                                       │ 4. 纯净流输出
                                       ▼
                ┌──────────────────────────────────────────────┐
                │        桌面播放器 (ArtPlayer + hls.js)        │
                │        • 咪咕原画/超清/外网源 秒级渲染       │
                │        • 画中画 / 影院模式 / 全屏快捷键      │
                └──────────────────────────────────────────────┘
```

### 4.1 核心攻坚点：流代理与 M3U8 重写（必须做对）
各大直播流 CDN（咪咕/腾讯等）均校验 `Referer`。本地 Sidecar 核心只需实现一个通用的代理接口：
1. **重写分片路径**：读取入口 `.m3u8` 文本，使用正则将每行 `.ts` 路径及 `#EXT-X-KEY:URI` 改写为走本地代理：
   ```
   http://localhost:3000/api/proxy?url=<encodeURIComponent(tsUrl)>&headers=<encodeHeaders>
   ```
2. **伪造请求头**：代理请求上游 CDN 时，携带配置的伪造请求头（如 `Referer: https://live.miguvideo.com/`）；
3. **流式转发 (Pipe)**：对分片数据不做任何内存驻留，直接 `upstreamResponse.body.pipe(res)`，极速转发且不占内存。

### 4.2 队名对齐规则（Matcher）
* 基于 `teams.json` 与中文别名表（如 `曼城=曼彻斯特城`，`国米=国际米兰`，`拜仁=拜仁慕尼黑`）；
* 抓取到的标题按 `vs / v / 对` 切分，若双队匹配且开球时间相差 $\le 2\text{h}$，直接绑定为该场比赛的可用线路。

### 4.3 极简双层降级（绝不白屏）
1. **主选（Tier 1）**：解析成功的 `.m3u8` / `.flv` 直链，通过 `ArtPlayer` 内置播放；
2. **兜底（Tier 2）**：若部分比赛加密无法提取直链，降级为**沙箱 Iframe 内嵌**或提供**【↗ 直达原站观看】**按钮（自动带上对阵队名搜索），确保只要网上有源，永远能看。

## 五、系统架构与极简技术栈

### 5.1 极简全栈架构
```
nightowl-web/
├── server/                      # 极轻量 Node.js 本地后台 (约 3-4 个核心文件)
│   ├── index.js                 # Hono/Express 服务入口、静态资源托管
│   ├── scraper.js               # 88看球/JRS 抓取与队名对齐
│   ├── proxy.js                 # M3U8 分片重写与流媒体代理
│   └── rules.json               # 站点提取正则与请求头配置 (外置可改)
└── src/                         # 前端应用 (React 18 + Vite + Tailwind)
    ├── core/engine.js           # 移植自原项目的算法大脑
    ├── data/                    # 1,897 场全量赛程与 111 支球队字典
    ├── components/              # HeroCard, ScheduleList, WatchPanel, ArtPlayer
    └── App.jsx                  # 桌面双栏布局
```

### 5.2 技术选型清单
* **前端**：`React 18 + Vite + Tailwind CSS`（现代、轻快、开发心智极低）；
* **播放器**：`ArtPlayer` + `hls.js` + `mpegts.js`（桌面环境三大主流浏览器全兼容）；
* **后台服务**：`Hono` 或 `Express` on Node.js（直接复用当前环境的 Node，无需安装额外复杂运行库）；
* **网页解析**：`cheerio`（快速提取 HTML 房间列表）。

## 七、敏捷开发里程碑（4 步上线）

以**“最快速度跑通第一场比赛观看”**为唯一目标，严控执行次序：

```
Step 1 (骨架与算法) ──▶ Step 2 (播放器与流代理) ──▶ Step 3 (抓取对齐打通) ──▶ Step 4 (联调交付)
```

| 步骤 | 目标 | 核心产出与验收指标 |
| :--- | :--- | :--- |
| **Step 1：双栏骨架与算法移植** | 建立 Vite + React 工程，导入赛程与算法 | 桌面双栏渲染正常，今晚之选、0-1 背包、1,897 场日历筛选秒开。 |
| **Step 2：播放器与流代理打通** | 集成 ArtPlayer，实现 `/api/proxy` 流重写 | 手动输入一个防盗链 m3u8，右侧播放器能够流畅播放，无 403 报错。 |
| **Step 3：单源对齐与一键开播** | 编写 88看球/JRS 抓取规则，完成队名对齐 | 点击赛程卡片【🔴 立即观赛】，右侧大屏自动换源出画面。 |
| **Step 4：体验打磨与交付** | 多线路切换、画中画、沙箱内嵌兜底 | 焦点比赛多线路秒切，提不到流时沙箱保底，打包一键启动命令。 |
