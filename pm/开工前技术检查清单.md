# 夜猫看台 · 开工前技术检查清单

> **定位**：本清单承载**实现级细节**，与产品方案解耦。方案保持极简，细节在此逐条打勾。
> **用法**：每个 Step 开工前过一遍对应段落；改代码时若发现新坑，直接补进对应分组。

---

## Step 1 · 骨架与算法移植

- [ ] **模块体系转换**：`engine.js` 为 CommonJS（`module.exports`），需改为 ESM（`export` / `import`）；连带清理 `data.js` 里全部 `require`
- [ ] **清理小程序全局依赖**：`evaluate()` 内的 `getApp()` 分支必须删除，`followedTeams` / `followedLeagues` 改为**显式传参**
  - 若保留兜底，Web 端会恒定落成「6 个联赛全选」→ 铁律一（关注联赛 +8）永远为 0，且雷区预警的「非关注联赛」分支永不触发
- [ ] **偏好存储迁移**：沿用同名 localStorage 键 `followedTeams` / `followedLeagues`；同时**删掉**旧版「5 联赛自动补 UCL」的兼容 shim
- [ ] **档位唯一入口**：所有睡眠档位判定走 `tierOf(m) → sleepTier(m.t)`，**禁止读取数据中的静态档位字段**
  - 原实现读的是烘焙字段 `s`；该字段由构建脚本写入，运行期直接取用。改为运行时计算后，数据同步会带档位自动重算
- [ ] **背包算法保持二维 DP**：一维滚动数组会导致 pick 标记被覆盖、无法正确回溯，勿"优化"
- [ ] **长列表虚拟化**：全量赛程（约 1,897 条）必须走虚拟滚动（`virtua` / `react-window`），否则赛季中后期滚动卡顿
- [ ] **排序一律用时间戳**：禁用 `t` 字符串直接比较（凌晨场次排序会错位）
- [ ] **定时器清理**：Hero 倒计时、预热轮询在组件卸载时必须 `clearInterval`
- [ ] **数据文件格式统一**：原项目存在 JSONL 与标准 JSON 两套格式，新项目统一为单一格式，避免解析歧义

## Step 2 · 本地服务与流代理

- [ ] **流转发写法**：必须使用 `Readable.fromWeb(upstream.body).pipe(res)`。
  **Node 原生 `fetch` 返回的是 WHATWG `ReadableStream`，没有 `.pipe()`**（实测 Node v22 / v26 均抛 `TypeError: b.pipe is not a function`）
- [ ] **监听地址**：仅 `127.0.0.1`，绝不 `0.0.0.0`
- [ ] **目标域名白名单**：`/api/proxy` 只允许放行已配置的直播域名，拒绝任意 URL
- [ ] **请求头白名单**：只放行 `Referer` / `User-Agent` 等必要字段，不透传任意头
- [ ] **请求能力**：透传 `Content-Type`；**支持 `Range` 请求**（拖动与分片必需）
- [ ] **查询串透传**：完整保留上游 `query` / `token`，签名 URL 参数不可丢弃
- [ ] **缓存分级**：`m3u8` 索引不缓存；`.ts` 分片可长缓存
- [ ] **流量控制**：并发上限 + 单请求超时；赛前批量预热时必须限速
- [ ] **失败语义**：区分「上游无源」与「网络失败」，后者不闩锁、不缓存失败状态
- [ ] **M3U8 重写覆盖表**（逐条验一遍，缺一条就会出现"能起播但一拖进度条就崩"）：普通分片行 / `#EXT-X-STREAM-INF` 变体 URI / `#EXT-X-KEY` / `#EXT-X-MAP` / `#EXT-X-MEDIA` / `#EXT-X-I-FRAME-STREAM-INF` / `#EXT-X-PART` / 相对路径绝对化

## Step 3 · 数据保鲜与抓取

- [ ] **`st` 落库取值域**：只写 `sched` / `done` / `pp`；进行中状态**不落库**，由 `matchState()` 推导
  - 若写入其他值，`pickToday` / `planWeek` / `minefield` 的 `st === 'sched'` 硬过滤会把正在进行的焦点战排除，Hero 会在开球瞬间消失
- [ ] **`tbd` 解除后的连带校验**：确认档位随新时间自动变化（依赖 Step 1 的「档位唯一入口」）
- [ ] **规则与别名表校验脚本**：提取规则与队名别名表是唯一外部依赖契约，加一个校验脚本防手改笔误
- [ ] **单源失败隔离**：一个源站挂掉不影响其他线路，界面上体现源站健康度
- [ ] **Matcher 时间比较用绝对时间戳**：不可比日期字符串（凌晨场次归前一晚，会差一天）
- [ ] **置信度分级落位**：高置信直连播放 / 中置信二次确认 / 低置信只给直达原站
- [ ] **纠正回路**：提供「这不是这场比赛」入口，写入本地黑名单
- [ ] **界面区分**：抓取失败 ≠ 今天没有比赛，两者提示文案必须不同

## Step 4 · 桌面外壳与体验

- [ ] **内嵌页广告处理**：广告域名拦截（请求层）+ 元素选择器隐藏（注入层），规则外置于 `adblock.json`
- [ ] **系统通知**：赛前 15 分钟提醒；首次运行申请权限并处理拒绝分支
- [ ] **全局快捷键**：注册前检测冲突，提供关闭开关
- [ ] **单实例锁**：避免重复启动产生两个服务进程与端口占用
- [ ] **服务随窗口起停**：窗口关闭时确保子进程被回收，不留孤儿进程
- [ ] **预热 TTL**：预取的线路地址设有效期，超时后点击需重新解析

## 通用纪律

- [ ] 依赖一律装在本项目 `node_modules`，不使用全局安装
- [ ] 数据更新走脚本，不手工编辑数据文件
- [ ] 提取规则 / 别名表 / 广告规则三份配置均外置，改规则不重新构建
- [ ] 本机 `127.0.0.1` 边界不可放宽；不做对外分发形态
