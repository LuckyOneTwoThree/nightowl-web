## 五、对账结论

**一句话：数据层能支撑的产品体验，比设计稿呈现的要"薄"一档；但比"什么都做不了"要厚得多。**

| 维度 | 判定 |
| :--- | :--- |
| 核心决策链路（今晚之选 / 睡眠档位 / 夜猫指数 / 背包 / 雷区） | ✅ **100% 可达**，算法输出完整可复算 |
| 赛程浏览链路（日历 / 筛选 / 防剧透 / 队徽 / 比分） | ✅ **可达**，仅需补 SCG 枚举 |
| 信息型内容（德比名 / 故事线 / 球队身份 / 冷知识） | ✅ **可达**，但覆盖不均是硬约束（93.3% 无看点信号） |
| 数据型深度内容（xG / 控球 / 阵型 / 节律 / 码率） | 🔴 **全部不可达**，设计稿中的这一层必须整体剥离 |

> **产品判断**：剥离这一层深度数据，不会让产品变差——因为本产品的定位是"**今晚该熬哪一场 + 一键就能看**"，而不是"战术数据终端"。用睡眠成本、故事线、德比、主队情感来支撑看点，本来就是原小程序被验证过的路子；把它做好，比堆砌假 xG 更符合产品人格。

**下一步**：以本表为判据，① 裁决决策 D1–D4 与 D5–D7；② 产出设计稿字段级整改清单；③ 按《需求规格说明书》与《开发任务计划》推进。
