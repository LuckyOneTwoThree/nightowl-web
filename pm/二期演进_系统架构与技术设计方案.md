### 1.1 `src/core/` 跨运行环境约束（强制）
1. **禁用 Node 与浏览器专属 API**：不得使用 `Buffer`、`node:crypto`、`localStorage`、`window`；编码与字节计算统一使用 `TextEncoder` / `TextDecoder`，时间统一使用 `Date.UTC` 与 [engine.js](file:///Users/lucky/Desktop/HelloWorld/Git_Project/nightowl-web/src/core/engine.js) 的 `ts()`。
2. **输出语义与零剧透隔离**：`drama.js`、`radar.js` 输出枚举与中性字段，禁止向无剧透视图暴露原始比分文本或 `side` 属性；中文文案由各自视图层或统一文案映射表呈现，方便双端保持语境贴合。

## 二、核心模块详细设计

### 2.1 M1：`src/core/drama.js` — 无剧透剧情心电图引擎

#### 2.1.1 核心接口契约
```js
/**
 * @typedef {{
 *   available: boolean,       // false 表示既无比分也无可用事件
 *   hasEvents: boolean,       // true 表示具备时间轴事件明细
 *   tags: Array<{ id: string, label: string, tone: 'accent'|'warn'|'neutral', priority: number }>,
 *   pulseMinutes: number[],   // 仅保留中性高能事件分钟（0..105），不含 side/type/team
 *   degradedReason: null | 'no-events' | 'not-finished'
 * }} DramaSummary
 */
export function summarizeDrama(match, recapEvents = null)
```

#### 2.1.2 核心判定逻辑（防御性防剧透）
1. 解析 `match.sc`（如 `"2-1"` → `{ h: 2, a: 1 }`）；未完赛或无比分且无事件时直接返回 `available: false`。
2. 对 `recapEvents` 过滤并归一化：仅保留 `type` ∈ `['goal', 'own', 'red', 'penalty']` 的事件，提取分钟数 `parseClockMinute(ev.clock)`（如 `"90+4'"` → `94`，限制显示区间 `0..105`）。
3. **重放领先关系轨迹（内部临时状态，函数返回即销毁）**：
   - 按分钟升序遍历有效进球事件（`goal` / `own`），累计临时差值 `diff = tempH - tempA`；
   - 记录 `sign(diff)` 序列（忽略 `0`）：若存在 `+1 → -1` 或 `-1 → +1` 跃迁 → `hasComeback = true`（`剧本反转 🔄`）；
   - 记录从非 `0` 回到 `0` 的次数 `equalizedCount`：若 `>= 2` → `isSeeSaw = true`（`绝平拉锯 ⚖️`）；
   - 若存在分钟 `>= 85` 的进球且**最终分差 `abs(h - a) <= 1`** → `hasLateDrama = true`（`终场悬念 🎭`）。
4. **标签降级决策**：
   - 若 `!hasEvents`：仅基于终场比分判断 `h + a >= 4`（`进球大战 ⚡`）与 `h === 0 && a === 0`（`颗粒无收 💤`）；`pulseMinutes` 置 `[]`，`degradedReason = 'no-events'`；
   - 按优先级排序截断最多 `2` 个标签返回；**返回对象通过构造白名单字段生成，绝对不带 `h`、`a`、`side`、`score`、`winner` 字段**。

### 2.3 M3：`src/core/second-half.js` + `src/core/radar.js` + `server/radar-watcher.js`

#### 2.3.1 双端通用的下半场切入账本（`src/core/second-half.js`）
```js
export const SECOND_HALF_OFFSET_MIN = 60;
export const WAKE_LEAD_MIN = 5;

export function planSecondHalfCutIn(match, sleepProfile, nowTs = Date.now())
```
* **输出结构**：
  - `eligible`: 布尔（`!match.tbd && match.st === 'sched'` 且夜猫时段属于跨夜凌晨场 `00:00–05:30`）
  - `cutInAt`: `kickoff + 60 * 60000`（如 `05:00`）
  - `alarmAt`: `cutInAt - 5 * 60000`（如 `04:55`）
  - `endAt`: `kickoff + 120 * 60000`
  - `preSleepMinutes`: 从 `Math.max(nowTs, suggestedBedtimeTs)` 到 `alarmAt` 的连续可睡分钟数
  - `savedNightMinutes`: 对比“不睡硬熬到开球后看全场”节省的熬夜区间说明（如省掉前 60 分钟干等+上半场时间）

#### 2.3.2 桌面端无剧透悬念雷达（`src/core/radar.js` + `server/index.js`）
* **纯函数判决器** `evaluateRadarSuspense(match, liveSnapshot, context)`:
  - **严格规则**：
    - 若 `!liveSnapshot || liveSnapshot.state === 'scheduled' || liveSnapshot.score?.h == null` → 返回 `{ verdict: 'UNAVAILABLE' }`；
    - 计算内部临时值 `diff = Math.abs(liveSnapshot.score.h - liveSnapshot.score.a)`、`totalGoals = h + a`、`hasRedOrPen`、`isTopClash = context.isDerby || context.isFollowed || context.star >= 2`；
    - 若 `diff >= 3` → `{ verdict: 'GARBAGE_TIME' }`；
    - 若 `diff <= 1 && (totalGoals >= 1 || hasRedOrPen || isTopClash)` → `{ verdict: 'WORTH_WAKING' }`；
    - 若 `totalGoals === 0 && !hasRedOrPen && !isTopClash` → `{ verdict: 'DULL_DRAW' }`；
    - 兜底 → `{ verdict: 'WORTH_WAKING' }`（宁可不误杀，也避免错漏重要胶着局）。
  - **防剧透审计**：返回值仅包含 `{ matchId, verdict, minuteLabel }`，**严禁回传 `score`、`goals`、`redCount`、`leadingSide`**。
* **桌面端节能调度（`server/index.js` / `electron/main.cjs`）**：
  - 仅在有盯盘场次（本地限制最多 **2 场**）且当前时间落入 `[kickoff + 55min, kickoff + 70min]` 时才发起至多 2 次 `/api/live` 查询（复用 20 秒缓存）；
  - 一旦做出最终判决（或超过 `kickoff + 70min` 降级发出 `UNAVAILABLE`），立即将该场从本晚雷达活跃轮询队列移除，触发对应桌面 `Notification`（带全局开关与防重复触发幂等键 `night|matchId|radarFired`）。
* **Android 端清晰降级**：
  - 由于 Android 后台受 Doze 策略限制无法在锁屏深夜稳定轮询接口，手机端 **只开放** M3 前半部分（下半场 `60'` 切入时间试算 + `expo-notifications` 定点在 `alarmAt` 发出“下半场切入窗口提醒”）。设置页明确写明能力边界，不虚标“手机锁屏实时判悬念”。

### 2.6 M6：局域网一扫同步 & 回被窝接力（安全边界核心设计）

> ⚠️ **安全重中之重**：本项目核心安全约束是 `server/index.js` **严禁监听 `0.0.0.0` 对外暴露 `/api/proxy`**（防止把本机变为局域网/开放 HTTP SSRF 代理）。

#### 2.6.1 隔离双端口架构（Absolute Isolation）
* **主业务服务（端口 `3100`）**：**保持 100% 绑定 `127.0.0.1` 不变**，一行不改其监听地址！
* **独立临时配对微服务器（`server/lan-pair.js`）**：
  - 默认**完全不启动（未监听任何局域网端口）**；
  - 仅当用户在桌面端点击「开始局域网同步 / 生成接力码」时，临时创建独立 `http.Server` 绑定局域网内网 IP（或临时随机端口 `0`），**硬编码最大存活时间 `TTL = 120 秒`**（到点自动 `.close()` 销毁，或同步完成一次即立刻 `.close()` 也可点击关闭）；
  - **严格路由白名单**：该微服务器**只挂载 3 个路由**：
    1. `GET /pair/info?token=xxx`：校验一次性高熵随机 Token 与 6 位 PIN（防同局域网嗅探猜测），仅返回桌面端状态快照版本与摘要；
    2. `POST /pair/sync`：受限于 `256KB` body 上限与 Strict JSON Schema 校验，执行白名单状态合并并返回合集；
    3. `GET /pair/handoff?token=xxx`：返回单场接力包 `{ matchId, title, lines: [{ label, url, proxyRequired }] }`；
  - **其余一切路径**（尤其 `/api/proxy`、`/api/fixtures` 等）在该微服务器上**根本不存在，全部返回 `404`**。

#### 2.6.2 协议与零新增原生依赖手机对接方案
1. **桌面生成二维码 + 6 位数字配对码**：
   - 使用纯 JS SVG 生成二维码展示（无重型依赖），编码 URI：
     `nightowl://pair?host=192.168.x.x&port=XXXXX&token=YYYYYY&mode=sync|handoff`
   - 同时界面明文展示：`局域网地址 192.168.x.x:XXXXX` + `6 位配对码`。
2. **手机端零新原生依赖接入**：
   - **路径 A**：手机 `mobile/app.json` 已注册自定义 `scheme: "nightowl"`（借助 Expo Router 深链支持），用安卓系统相机/扫一扫识别二维码直接拉起 App 路由 `app/pair.tsx`；
   - **路径 B**：若系统相机拦截自定义协议，App「我的 → 局域网同步」界面直接提供一个简洁表单输入 IP:端口 与 6 位配对码即可完成连接，**不需要引入 `expo-camera` 原生相机权限或额外打原生包风险**。

#### 2.6.3 双向状态增量合并算法（`src/core/sync-bundle.js`）
| 状态项 | 合并策略 | 防剧透与防退化保障 |
| :--- | :--- | :--- |
| `prefs` | 按最后修改时间戳 `prefsUpdatedAt` 取最新一份（LWW） | 仅同步白名单 12 个偏好键 |
| `weekOverrides` | 按 `weekKey` 取最新，或同周内 `pinned` / `excluded` / `blockedNights` 按条带时间戳合并 | 冲突时保留显式用户操作 |
| `watchLater` 队列 | 按 `id` 合并并集，遵守 `status` 单向收敛规则：**`watched` 优先级高于 `pending`**；上限裁剪 10 条（沿用 `queue.js` 规则） | 不会因旧端同步把“已看”退回“未看” |
| `revealedIds` | **只增不减集合并集（Union）** | 防止一端已揭晓场次在另一端误触发防剧透混淆 |
| `watchedLedger` (M4) | 按 `matchId` 对比 `updatedAt` 取较新记录合并 | — |

#### 2.6.4 「回被窝接力」直连与代理流分流逻辑
* 桌面播放器很多线路依赖 `127.0.0.1/api/proxy` 带定制 `Referer/Origin` 绕过防盗链，手机无法直接请求 `127.0.0.1`：
  - **情况 1（纯公开直链，无定制 Header 需求）**：`handoff` 包直接下发原生 `.m3u8` URL，手机 `WatchSheet` 秒开播放；
  - **情况 2（受保护代理流）**：明确标注 `proxyRequired: true`，手机接力落地后自动停留在目标场次 `WatchSheet` 并**自动触发手机端公开线路重抓（`scraper.js`）**，同时 UI 诚实提示「桌面当前为本地代理路线，手机已为你切换至该场次并检索公开直链」。

## 三、UI 与视觉规范契合点（不破坏现有设计语言）

1. **视觉 Token 继承**：继续使用夜间深空黑底 `#0A0D14`、卡片 `#131722`、边框 `#232A3B`、琥珀金 `#FFB800` 强调高价值状态、青色 `#44E2CD` 表示收益/节省睡眠、JetBrains Mono 展示一切数字与分钟刻度。
2. **手机端可触控合规**：所有新增胶囊开关（沙盘三态、情绪印章 4 选 1、半场切入切换）高度严格 `≥ 44dp`，必须通过 `mobile/npm run audit:touch` 静态检查。
3. **信息密度防过载原则**：
   - `MatchRow` 列表行严格控制不膨胀：剧情心电图只渲染 `2` 枚短标签 + 极细 4px 脉冲条；
   - 沙盘、下半场切入试算、14 天魔鬼预警优先嵌入详情页/规划页既有卡片内折叠槽位，不强占首屏焦点流。
