## 一、产品定位与边界

### 1.1 一句话定位

专为熬夜球迷打造的**本地纯净观赛工作台**：**3 秒决策今晚看哪场，1 次点击极清看到画面。**

### 1.2 价值主张（两条，缺一不可）

| # | 价值 | 用户可感知的表达 |
| :--- | :--- | :--- |
| V1 | **算法算得准** | "它说的今晚之选，就是我会选的那场" |
| V2 | **极清看球无广告** | "点一下就有画面，没有弹窗" |

> **产品反例警示**：若 V1 不准（推荐违和）或界面数据为假（编造统计），产品失去存在理由。**这两个是最硬的底线。**

### 1.3 硬边界（不可放宽）

| 约束 | 内容 |
| :--- | :--- |
| 服务监听 | 仅 `127.0.0.1`，绝不 `0.0.0.0`，不对外暴露 |
| 部署 | 不部署公网、不做可一键托管的分发形态 |
| 使用范围 | 仅本人本机观看，不向他人提供 |
| 数据 | 全部本地存储，零云依赖、零登录、零鉴权 |
| 内容红线 | 界面不得出现**无数据源**的字段（判据见对账表） |

### 1.4 明确不做（本期）

| 不做项 | 理由 |
| :--- | :--- |
| 社交玩法（盲评猜球 / 打卡榜 / 德比法庭 / 盲盒 / 海报） | 个人工具无多人场景 |
| 云端服务（微信云函数 / 云数据库 / 鉴权） | 零云端成本 |
| 移动跨端（iOS 转封装 / 扫码 / 局域网配对） | 已明确本地单机 |
| 2×2 多场同看网格 | 延后（高级体验，前期聚焦单场高可用） |
| 补番推荐（已赛高分回看） | 延后（依赖赛果完整性） |
| 战术深度数据（xG / 控球 / 阵型 / 球员数据） | 数据层完全没有；**且不在产品定位内** |

## 二、用户与核心场景

### 2.1 用户

单一用户画像：**本人。** 欧洲足球球迷，深夜观赛，同时是数据敏感型用户（会质疑推荐是否合理）。

### 2.2 三个核心场景

| # | 场景 | 时间 | 用户心智 | 承接页面 |
| :--- | :--- | :--- | :--- | :--- |
| S1 | **"今晚看哪场？"** | 晚间 20:00 – 凌晨 04:00 | 3 秒内要知道答案，并立刻开播 | 今晚视图 + 播放器 |
| S2 | **"这周我只有 4 小时额度，该熬哪几场？"** | 周中 / 周末前 | 算身体账，要最优组合 | 本周视图 |
| S3 | **"皇马哪天踢马竞？昨晚比分多少？"** | 随时 | 检索赛程 | 赛程视图 |

### 2.3 场景与状态的关系（关键）

| 场景 | 常见状态 | 设计要求 |
| :--- | :--- | :--- |
| S1 | 有焦点战进行中 / 有焦点战即将开赛 / **今晚无球** | **无球日是必须支持的常态**，不是异常 |
| S2 | 本周有可入包场次 / 预算极度紧张 | 预算紧张时算法结论要说人话 |
| S3 | 有赛程 / 有 tbd 场次 / 筛选无结果 | tbd 与"今天没有比赛"必须区分 |

## 三、信息架构与页面地图

### 3.1 结构（D2 已排定）

**采用方案 A。** 三视图 Tab **只在顶栏**，作为唯一导航入口。

| 元素 | 规定 |
| :--- | :--- |
| 顶栏 Tab | `[🌙 今晚] [📊 本周] [📅 赛程]` —— **唯一导航入口** |
| 左栏 Tab | ❌ 不存在（Stitch 稿中的重复 Tab 删除） |
| 左侧图标 rail | ❌ 不存在（Stitch 稿新增的 56px rail 删除，宽度归还内容区） |
| 左栏宽度 | `min-w-[420px]` / `max-w-[520px]`（三处不一致已统一为 520px） |

> **导航唯一性铁律**：三大主视图的切换入口不得在任何其他区域重复出现。
> 「关注联赛」是**算法偏好**（影响 +8 加成），与列表筛选药丸语义不同，必须放在设置抽屉，不得与筛选器混排。

### 3.2 页面地图

```
夜猫看台（单窗口）
├─ 顶栏（Global Header，全页面常驻）
│   ├─ Logo + 产品名 + 版本角标
│   ├─ 三视图切换：[🌙 今晚] [📊 本周] [📅 赛程]
│   ├─ 北京时间（实时，等宽字体）+ 进行中场次计数
│   └─ 关注球队药丸 + [⚙ 偏好设置]
│
├─ 主工作区（双栏 38% / 62%，左栏 min 420 / max 500px）
│   ├─ 左栏（决策与列表区）
│   │   ├─ 今晚视图：Hero 卡 + 今晚场次切片
│   │   ├─ 本周视图：预算规划器（双模态）+ 精选组合 + 周历透视 + 雷区
│   │   └─ 赛程视图：筛选栏 + 虚拟滚动长列表
│   └─ 右栏（观赛大屏与情报区）
│       ├─ 播放容器（16:9）
│       ├─ 线路切换台
│       └─ 比赛情报板
│
└─ 设置抽屉（右侧滑出，480px，覆盖式）
    ├─ 关注球队 / 关注联赛（影响算法 +8）
    ├─ 睡眠成本与防剧透规则
    └─ 数据保鲜与本地服务状态
```

### 3.3 双栏联动规则（核心机制）

| 规则 | 内容 |
| :--- | :--- |
| 驱动源 | 单一状态 `activeMatchId` |
| 首屏初始化 | 打开即运行 `pickToday()`，`activeMatchId` **自动锁定为今晚之选**，右栏就绪，用户零点击看到焦点 |
| 左栏行为 | 选中卡片显示 4px 琥珀金左边框高亮 |
| 右栏派生 | 按 `matchState()` 分派：`live` → 直播流；`sched` → 赛前情报 + 倒计时；`finished` → 战报；直链失败 → 内嵌降级 |
| 切换视图 | **切换左栏视图时右栏播放绝不中断**（码率、时间轴、全屏状态 100% 保持） |

### 4.2 睡眠成本档位定义（算法唯一入口）

| 档位 | 成本 | 开球时间（北京时间） |
| :--- | :--- | :--- |
| S0 零成本 | 0.0h | ≤ 22:30 |
| S1 轻度 | 1.0h | 22:30 – 00:30 |
| S2 黄金修仙 | 2.5h | 00:30 – 02:30 |
| S3 重度死线 | 3.5h | 02:30 – 04:00 |
| S4 极限折磨 | 4.5h | ≥ 04:00 – 07:00 |

> **铁律**：档位一律**运行时**由 `tierOf(m) → sleepTier(m.t)` 计算，**禁止读取数据中的静态档位字段 `s`**（该字段由构建脚本写入，时间更新后不会跟随）。
> **`tbd` 场次不显示档位徽章**（时间不可信，档位无意义）。

### 4.3 偏好项（localStorage）

| 键 | 内容 | 影响 |
| :--- | :--- | :--- |
| `followedTeams` | 关注球队 ID 数组 | `evaluate()` → `isFollowed` → 星级提级 + 指数 +25 |
| `followedLeagues` | 关注联赛 ID 数组 | **铁律**：仅当选择数 < 6 时，关注联赛场次 +8；全选 6 个时加成为 0 |
| `weeklyBudget` | 默认周预算（小时） | `planWeek()` 输入 |
| `spoilerFree` | 防剧透开关 | 已赛场次比分默认模糊 |
| `notifyBefore15` | 赛前 15 分钟通知 | Electron 通知 |

> **迁移要求**：沿用同名键。**必须删除**旧版"5 联赛自动补 UCL"的兼容 shim，并且**禁止任何形式的全局兜底默认值**——旧版靠小程序 `getApp()` 兜底，会让 `followedLeagues` 恒为 6 个，导致铁律一（+8 加成）永远为 0、雷区"非关注联赛"分支永不触发。

### 5.3 赛程视图（Schedule）· P0

## 七、算法需求规格

> 算法继承自 `miniprogram/utils/engine.js`（499 行纯函数），改写为 ESM。

### 7.1 调用契约（违反即出错）

| 函数 | 输入集合 | 取数方式 |
| :--- | :--- | :--- |
| `pickToday` | **今晚的场次** | 按 `owlDay(m.t) === nightOf(now)` 过滤。**绝不可传全量赛程** |
| `planWeek` | **本周的场次** | `weekStartBJ()` → +7 天 |
| `minefield` | 本周窗口 | 同上 |
| `nextFocal` | 全量未来场次 | 全量 + 时间戳比较 |
| `replays` | 全量已赛场次 | `isFinished()` 过滤 |

### 7.2 能力清单（7 项）

| 能力 | 函数 | 输出 |
| :--- | :--- | :--- |
| 今晚之选 | `pickToday` | `{ hero, extras }` |
| 睡眠成本分档 | `sleepTier` / `tierOf` | S0–S4 |
| 夜猫指数 | `owlIndex` | `W ÷ (1 + 睡眠成本)` |
| 本周背包 | `planWeek` + `knapsack` | `{ best, alt, budget, used }` |
| 雷区预警 | `minefield` | 场次列表 + `reason` |
| 无球日降级 | `nextFocal` + `countdown` | 下一场焦点战 + 倒计时 |
| 补番推荐 | `replays` | 已赛高分场次（延后启用） |

### 7.3 三条铁律

| # | 铁律 |
| :--- | :--- |
| 1 | **关注联赛加成 +8 仅在已选关注联赛 < 6 时给予**；全选 6 个时不加分 |
| 2 | **`tbd` 排除**：不担任今晚之选、不进背包、不进雷区，**也不显示档位徽章** |
| 3 | **完赛状态兼容**：`isFinished()` 同时认 `'done'`（ESPN 源）与 `'ft'`（历史手工数据） |

### 7.4 时区口径（不可简化）

数据时间形如 `2026-08-16T01:30`，是**北京墙钟、无时区后缀**。全部换算走纯 UTC 算术，**禁止 `new Date(t)` 做本地解析**（否则非 +8 时区设备上"今晚之选"整体错位）。

| 函数 | 职责 |
| :--- | :--- |
| `ts(t)` | 北京墙钟串 → 真实时间戳（`Date.UTC(...) - 8h`） |
| `owlDay(t)` | 夜猫口径展示日（00:00–06:00 归属前一夜） |
| `nightOf(now)` | 夜猫口径"今晚"，设备时区无关 |
| `weekStartBJ(now)` | 本周周一日期串 + 周一 00:00 真实时间戳 |
| `matchState(m, now)` | 推导 `sched / soon / live / ended_pending / finished / pp` |

**状态机**：`sched` →（赛前 30 分钟）`soon`（前端派生态，不落库）→ `live`（开球至 +120 分钟）→ `ended_pending`（等比分）→ `finished`

### 7.5 算法修正口径（**已排定 · 2026-09-12**）

> 原 §7.5 引自主方案 §3.6，经 `spike/algo-baseline/` 实测后**定性有误**。本节为更正后的确定口径。
> 完整标定数据见 `spike/algo-baseline/CALIBRATION.md`。

#### 7.5.1 【已证伪】主队加成不影响 Hero 排序

实测（90 夜窗口，加成取 0/5/10/15/25/40）Hero 结果差异 **0/90**。原因：`pickToday` 排序第 1 优先级是 `isFollowed` 布尔硬比较，权重只改数值、不参与排序。

**"主队加成会不会让 Hero 选错"这个问题不成立。** 保留 `followedBonus = 25` 不变。

#### 7.5.2 指数公式"零成本特权" → `watchCost = 0.5`

公式 `W ÷ (1 + 睡眠成本)` 让成本 0 获得乘性特权。实测后果：

| 场次 | 档位 | 星级 | 修正前 | **修正后** |
| :--- | :--- | ---: | ---: | ---: |
| SLA vs ARS（欧冠客场，04:00） | S4 | ★★ | 8.2 | **7.5** |
| — 对照 — 任意 S0 ★1 中立赛 | S0 | ★ | 10.0 | **6.7** |
| 曼市德比 | S1 | ★3 | 20.0 | 16.0 |
| 阿森纳主场皇马（欧冠） | S4 | ★★★ | 11.8 | 10.8 |

**确定口径**：分母改为 `(1 + 睡眠成本 + watchCost)`，`watchCost = 0.5`。

**取值依据**：`0.5` 是使判据（凌晨主队 > 傍晚 ★1 中立）成立的**最小可行值**。`0.25` 时仍不成立（7.8 vs 8.0）。对 Hero 排序**无影响（0/90）**。

#### 7.5.3 背包退化 → 零成本分离 + 数量上限 5（🔴 阻塞项已修）

背包重量 = `睡眠成本 × 2`，S0 场次成本 0 → **重量 0 → 不消耗容量 → 全部装入**。实测周预算 1.0h 也返回 20 场。

**确定口径**：
- `separateZeroCost = true` —— **主修法**：零成本场次不进背包，单独展示为「零成本顺带」区
- `maxPicks = 5` —— 安全上限，防止数据变化后再次失控

**修正后表现**（周预算 4.0h）：预算内 **1 场**（主队 S3，占用 3.5h）+ 「零成本顺带」**19 场**。

#### 7.5.4 Hero 低看点分档 → 阈值 15 / 5

`Hero 指数`分位：P0 `40.0` / P25 `18.0` / 中位 `7.5` / 最低 `2.0`（高度右偏）。

**确定口径**（`heroTierOf(index)`）：

| 档位 | 阈值 | 夜数 | 表现 |
| :--- | :--- | ---: | :--- |
| **高光卡** | 指数 ≥ 15 | 34 晚 (40%) | 完整 Hero 卡（「今晚唯一焦点」+ ROI + 看点叙事） |
| **标准卡** | 5 ≤ 指数 < 15 | 23 晚 (27%) | 去「唯一焦点」措辞，保留对阵 / 档位 / CTA |
| **弱化卡** | 指数 < 5 | 28 晚 (33%) | 「今夜无必看」+ 可看场次列表 |

**无球日（46 晚）** 单独处理：走「下一场焦点战倒计时」（沿用主方案 §二 既有设计）。

> **注意**：低看点夜**不并入倒计时**——当晚确实有球，剥夺选择反而不妥。倒计时只留给真正的无球日。
