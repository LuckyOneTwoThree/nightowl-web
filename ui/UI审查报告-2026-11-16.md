# 夜猫看台 · UI 设计审查报告

> 审查日期：2026-11-16
> 审查对象：桌面端（Electron 渲染，1440×820 实际视口）+ 移动端结构抽查
> 审查方式：**真实渲染截图 + DOM 量化审计**（不依赖主观印象）
> 复现路径：`.shots/audit-ui.mjs`（对比度/字号/热区/溢出/圆角统计）、`.shots/probe-geo.mjs`（几何与强调色分布）
> 本报告是优化依据，不是最终方案；P0/P1 的每一条都可以独立开工。

## 一、总评

**一句话：设计系统的"骨架"是同类产品上游水平，问题集中在"骨架之外"——空态、首屏重心、窄视口降级三处。**

现有实现最难得的地方是**约束被真的执行了**，而不是写在文档里。全站扫描结果：

| 纪律项 | 规范要求 | 实测违规 |
| :--- | :--- | :--- |
| 原生 Tailwind 色（emerald-500 等） | 0 | **0** |
| 任意色值 `bg-[#xxx]` | 0 | **0** |
| 任意层级 `z-[999]` | 0 | **0** |
| 任意字号 `text-[13px]` | 0 | **3 处 10px**（见 P0-4） |
| 文本对比度（WCAG AA） | 全部达标 | **3 处未达标，均为装饰性分隔点** |
| 图片 alt / 按钮可访问名 | 全部 | **0 / 0** |

这在自研产品里很少见。多数"设计系统"最终都退化成一份漂亮文档 + 一堆 `text-[15px]`，这个项目没有。

### 分维度评分

| 维度 | 评分 | 判断依据 |
| :--- | :--- | :--- |
| 视觉风格统一性 | **9.0** | 四级表面 + 两档描边 + 四档文本，全站无第五种层级 |
| 配色与语义分工 | **9.0** | live/resource/warn/danger/tier/result 各司其职，0 处挪用 |
| 组件一致性 | **8.5** | 原子层收口有效；仍有 3 处绕过 atoms 的局部实现 |
| 无障碍与可读性 | **8.5** | muted 5.36–7.29:1，全局 focus-visible，减动效单点声明 |
| 字体排版 | **7.0** | 层级正确但 11px 是最大字重群体，非"下限"而是"默认" |
| 布局结构 | **6.5** | 三栏骨架清晰，但左栏 400px 级空白与赛前舞台 3.4:1 失衡 |
| 交互细节 | **6.5** | 热区偏小（15px/16px/17px 三处系统性偏小） |
| 响应式适配 | **5.5** | 1280 以下时钟消失，无降级替代 |

**加权总评：7.6 / 10**

## 二、做得好的地方（不要在这些地方动手）

1. **语义色零挪用**。`live` 只碰直播红点，`resource` 只碰睡眠额度，`warn/danger` 只碰系统异常，睡眠档位走独立连续色阶。实测首页文本色仅 6 种，其中 4 种是灰阶——这是克制换来的。
2. **对比度是全站性的，不是局部性的**。1440 下逐文本节点测量：tonight 87 个、week 137 个、schedule 186 个节点，未过 AA 的只有 3 个，且全是 `·` 分隔符。`text-muted` 在 press 档（#232b3b）上仍有 5.36:1，说明 token 是按最差底色调过的，不是按 #0b0e15 调的。
3. **数字排版专业**。倒计时/指数/比分统一 `font-num` + `tabular-nums`，秒级时钟隔离在 `KickoffCountdown` 叶子组件，父级不随 1s 重渲染。
4. **无障碍底座完整**。`img` 全部有 alt、图标按钮全部有 aria-label、heading 层级 H1→H2→H3 完整、1 处 `aria-live`、`focus-visible` 有全局兜底、`prefers-reduced-motion` 只声明一次且真的降级。
5. **字体自托管 + 精确取舍**。JetBrains Mono 只声明 400 换取合成粗体的字重层级，省 94KB；`swap` + 本地 woff2，离线启动不等外网。

## 三、问题清单

### P0 · 影响核心任务或跨平台正确性（4 项）

#### P0-1　顶部时钟在 <1280px 直接消失，无降级
- **证据**：`src/components/TopBar.jsx:109` — `className="... hidden shrink-0 items-center gap-2.5 xl:flex"`。1120×700 视口实测顶栏只剩 Logo / 四个 Tab / 右侧动作区，**时间、日期、日间档全部不见了**。
- **为什么是 P0**：这个产品所有决策都锚定"北京墙钟"（今晚几点开球、还剩几小时睡）。把时间从界面移除，等于移除决策的第一参照系。而 1280×800 是最常见的笔记本分辨率，扣掉窗口边框正好落在断点以下。
- **建议**：拆成两档降级而非隐藏——`lg`（1024+）显示 `HH:MM` 单值（去掉日期与"日间档"），`xl`（1280+）显示完整胶囊。信息可以减，参照系不能没。
- **验收**：1120 视口下顶栏可见时钟，且不挤压 Tab 与右侧动作区（Tab 区允许收起文字只留图标）。

#### P0-2　周视图 7 个日格的点击热区仅 15px 高
- **证据**：DOM 实测 7 个 `role="button"` 日格尺寸为 `302×15`、`302×22`（含比赛的那天因内容撑高才到 22）。这是周视图里最高频的交互（切日 → 看当天场次）。
- **为什么是 P0**：15px 高的横条在密集堆叠下相邻间距不足 8px，误点相邻日期的概率很高；鼠标悬停的命中反馈也会闪烁不定。桌面端可用下限 24px，触屏（若未来接平板）需 44px。
- **建议**：日格最小高度 28px（内容区加大 `py`），或保持视觉高度不变但用 `::before` 把热区向上下各扩 6px（视觉不动、命中扩大）。
- **验收**：7 个日格的可点高度 ≥ 28px，且相邻格热区不重叠。

#### P0-3　左栏列表 `-mr-1` 造成 4px 溢出，被 `overflow-hidden` 裁切
- **证据**：左栏 355px − padding 32px = 322px 内容宽；列表容器 `scrollbar-thin -mr-1 ...` 实测 `scrollWidth 326 / clientWidth 322`，父级 `section` 带 `overflow-hidden`。即列表整体比容器宽 4px 并被裁掉。
- **为什么是 P0**：macOS 覆盖式滚动条下看不出来，但本项目**发布 Windows NSIS 包**——Windows 传统滚动条会吃掉 8–14px 宽度，叠加这 4px，行尾右对齐的"指数"数值会被切掉一部分。这是"本机看着好好的、用户那边数字缺角"的典型跨平台缺陷。
- **建议**：去掉 `-mr-1`，改用 `scrollbar-gutter: stable`（或 `pr-1` + 滚动条宽度补偿），让溢出为 0。
- **验收**：Windows 上列表行尾数值完整，`scrollWidth === clientWidth`。

#### P0-4　3 处 10px 字号，违反自身 11px 可读性下限
- **证据**：`DramaMeter.jsx:44`、`DramaMeter.jsx:57`（`0'` / `90'+`）、`SeasonReportModal.jsx:359` 使用 `text-[10px]`。而 `tailwind.config.js` 与 `index.css` 都明确写"可读性下限是 11px —— 中文回退 PingFang SC 后 10px 以下会糊"。
- **为什么是 P0**：这不是审美问题，是**自己定的规则被自己绕过**。一旦开了这个口，后续所有"差一点放不下"的地方都会用 10px 解决，字号阶梯会在半年内失效。
- **建议**：三处改 `text-2xs`（11px）。若 DramaMeter 的刻度标签确实放不下，改为减少刻度数量而不是缩字号。
- **验收**：`grep -rn "text-\[1[0-9]px\]" src/` 返回空。

### P1 · 显著影响观感与信息效率（7 项）

#### P1-1　首屏最常见的状态是"大面积空白"
- **证据**：今晚无赛时，左栏空态卡实测约 **260px 高**，内含一枚 32px 图标 + 两行 11/12px 灰字（"今晚没有已排期的比赛 / 下一场焦点已在上方展示，后续赛程可以在下方「接下来」里查看。"）。该卡上方还有约 100px 留白，整块区域占左栏可视高度的 **60%**。
- **问题**：这是产品的**默认第一眼**（白天打开、周一无赛时必然出现），却把最重要的 60% 面积交给一句话。而且文案是**死路**——它让用户"去下面看"，而不是给用户一个决定。
- **建议**：空态升级为"决策占位卡"，三段式：
  1. 下一场焦点（队徽 + 开球倒计时 + 档位/指数）—— 现在这些散落在别处；
  2. 本周最优一晚（`week-risk` 已算好，直接取第一名）；
  3. 一个主行动（"去看本周最优" / "加入明早补看"）。
  空态是"没有数据"的容器，也是"引导下一步"的最佳位置，现在只做了前者。
- **验收**：无赛日首屏左栏空白面积下降 50% 以上，且空态内含至少 1 个可点击的行动。

#### P1-2　赛前舞台 3.4:1，视觉重心散在两端
- **证据**：1440×820 下赛前舞台实测约 **1014×295**（3.4:1）。内容是：左队徽 x≈79、右队徽 x≈241（左栏内），主舞台上两侧队徽水平间距约 460px，中央一枚 44px 倒计时。
- **问题**：一块 3.4:1 的横条里，视觉重量被拉到左右两极，中间只剩数字，形成"哑铃"结构。而 16:9 视频在开播后受 `max-h-[46vh]`（≈377px）限制，1014 宽下画面约 670×377，左右各留约 170px 空白——**赛前和赛中都在浪费横向空间**。
- **建议**：二选一，不要折中：
  - **A（推荐）**：赛前态填满可用高度（`min(72vh, 16:9)`），把队徽靠近中央，倒计时下方补上"关键场次信息条"（档位/指数/看点一句），让赛前态成为真正的舞台而不是占位符；
  - **B**：明确降级为"信息条 + 大数字"，高度压到 200px 以内，把省下的空间给情报面板。
- **验收**：赛前舞台宽高比落在 1.6–2.2 或高度 < 200px 二选一，不允许停在 3.4:1。

#### P1-3　顶栏"居中"时钟组实测偏右 41px
- **证据**：`header` 用 `justify-between` 三组布局。实测时钟 `x=732..790`（中心 761），视口中心 720；整组（时钟+日期+日间档）`732..923`，中心 827，**偏右 107px**。
- **问题**：`justify-between` 只有左右两组等宽时才居中。这里是"看起来居中但不居中"，比明显靠左更让人不适——每次扫视都会觉得差一点。
- **建议**：中间组改 `grid-cols-[1fr_auto_1fr]`，或 `absolute left-1/2 -translate-x-1/2`（配合左右组 `pointer-events` 正常）。
- **验收**：时钟组中心与视口中心偏差 ≤ 2px。

#### P1-4　两级灰只差 17% 亮度，等于只有一级灰
- **证据**：`text-muted #94a0b2` 与 `text-faint #8a95a6` 亮度比 1.169（在 #0b0e15 上对比度 7.29 vs 6.37）。1440 首页用量 40 vs 34，周视图 58 vs 48——**几乎等量**。
- **问题**：两个 token 的对比度差只有 1.14×（ΔL* 约 4），在 11px 中文上不可区分。等于设计系统声称四级文本（primary/secondary/muted/faint），实际感知是三级。多一套 token 却没换来一级层级。
- **建议**：二选一：
  - **合并**：把 faint 并入 muted，灰阶从 4 档减到 3 档，减少一个没人能分辨的选择；
  - **拉开**：faint 抬到 `#9aa5b6` 附近（与 muted 对比度差 1.5× 以上），并明确分工（muted = 可读的辅助信息，faint = 不可读也不重要的占位）。
- **验收**：两档灰在同一屏上并排时，肉眼可区分；或灰阶只剩三档。

#### P1-5　同屏 7 档圆角，阶梯不可感知
- **证据**：周视图实测圆角分布 `2px×36 / 4px×12 / 6px×35 / 8px×7 / 12px×5 / 16px×2 / 9999px×31`——规范里的 7 档**全部同时在场**。
- **问题**：规范为每档写了语义（2px 柱条 / 4px 标签 / 6px 控件 / 8px 条目 / 12px 卡片 / 16px 弹窗 / full 队徽）。但 6px 与 8px 在 32px 高的元素上视觉差 2px，人眼分辨不出，于是"层级"变成"随机"。35 个 6px 和 7 个 8px 混用，实际传达的是"没有规则"。
- **建议**：收敛到 **3 档内容圆角**——8px（行/小卡）、12px（模块卡）、16px（浮层），2px 只留给赛果小方块，`9999` 只给队徽/圆环/进度条。控件从 6px 统一到 8px。
- **验收**：同屏内容圆角种类 ≤ 4 种（含 full）。

#### P1-6　三处系统性偏小的热区
- **证据**（1440 实测）：
  - `查看说明` 图标按钮 **16×16**，每屏 3–5 个（`atoms.jsx` 中 `h-4 w-4`）；
  - 周视图 `固定` / `换掉` 按钮 **36×17**，且两枚相邻并排；
  - "我的看台"额度滑杆可点区 **460×16**，真实滑轨仅 2px 高。
- **问题**：`固定/换掉` 是周视图最高频的决策操作，17px 高 + 紧邻 6px 间距，误点是必然。16px 的帮助图标在 11px 正文行内，实际上要"瞄准"。
- **建议**：热区统一提到 24×24（视觉不变，用 `p-1` 撑开）；`固定/换掉` 改为单枚切换按钮（`固定` ⇄ `已固定`），高度 28px；滑杆加 `py-2` 扩大拖拽带。
- **验收**：所有交互元素热区 ≥ 24×24。

#### P1-7　右栏折叠线路条孤立悬浮
- **证据**：线路面板折叠后为 **38×116**，位于 `x=1379`（距右边 23px、距主内容右侧约 40px），内含 4 个无文字图标（直播状态+线路数、刷新、外链、展开）。下方到屏底全是空白。
- **问题**：它控制的是"舞台的线路"，但视觉上跟舞台卡片没有任何连接；四个图标无语义标签，只能用悬停 title 猜。在 1440 首屏上它读起来像一个调试工具条。
- **建议**：把折叠态收进舞台卡片内部右上角（与"小窗 / 全屏"同组），或给竖条加一个 90° 竖排标签"线路"。目标：任何可点元素都能一句话说明它属于谁。
- **验收**：折叠态在视觉上归属舞台卡片，图标具备文字或竖排标签。

## 四、不建议动的三件事

设计优化最容易犯的错是"把没问题的东西也改一遍"。以下三条建议**保持现状**：

1. **不要引入浅色主题。** 深色是这个产品的物理属性（凌晨关灯看球），不是审美偏好。加浅色主题会逼所有语义色重新配平，收益为负。
2. **不要整体放大字号。** 11px 占比高是问题（P1-4 已覆盖），但把 11px 提到 13px 会破坏信息密度这个核心竞争力。正确方向是"减少 11px 的**职责**"（只留给元信息），不是"提高 11px 的**数值**"。
3. **不要给卡片加发光/玻璃拟态。** 现在的四级表面已足够表达层级，加光效直接违背"零眩光护眼"，且会让 6 个模块卡在同一屏上互相争抢。

## 五、落地建议（三批）
