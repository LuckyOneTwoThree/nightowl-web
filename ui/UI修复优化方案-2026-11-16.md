# 夜猫看台 · UI 修复优化方案

> 版本：v1.0 / 2026-11-16
> 依据：`ui/UI审查报告-2026-11-16.md`（量化基线 7.6 / 10）
> 目标：**7.6 → 8.6**，其中「响应式 5.5 → 8.0」「布局结构 6.5 → 8.0」「交互细节 6.5 → 8.5」
> 执行方式：三批串行，每批独立可验证、可回滚

## 〇、执行原则（先立规矩，再动手）

### 必须遵守

1. **不碰算法层**。`engine.js` / `owl.js` / `week-risk.js` / `decision-strip.js` 一律只读。本方案所有改动都在 `src/components/`、`src/index.css`、`tailwind.config.js`。
2. **不碰播放链路四条**。显式 `kind`、超时三层、闸门幂等、保底频道外置 —— P1-2 / P1-7 会动 `PlayerStage.jsx` 的**外壳布局**，但绝不进入线路解析与授权逻辑。
3. **不新增设计 token**。本方案只做三件事：修正断点、修正几何、收敛既有 token。唯一新增的数值是 `text-muted` 色值调整（D3）。
4. **任意值禁用令不松口**。所有改动只用 `tailwind.config.js` 里已有的档位类；`text-[13px]`、`z-[999]`、`bg-[#xxx]` 一旦出现即视为回归。
5. **每批改完必跑审计**。命令见 §五，四项指标必须单调改善，否则回滚该项。

### 明确不做

| 不做 | 原因 |
| :--- | :--- |
| 引入浅色主题 | 凌晨看球是产品物理属性，不是审美偏好 |
| 整体放大字号 | 信息密度是核心竞争力；要改的是 11px 的**职责占比**，不是 11px 的**数值** |
| 给卡片加发光/玻璃拟态 | 现有四级表面已足够表达层级，加光效违背零眩光 |
| 重排三大主视图的信息架构 | 顶栏 Tab + 左决策右舞台是对的，问题在每块区域内部 |
| 引进组件库（Radix/Headless UI 等） | 现有原子层已够用，引库会打破 token 纪律 |

## 一、三个需要你拍板的决策点

方案已给出推荐项与理由，未拍板的部分我按推荐项写好了代码级改法。

### D1　无赛空态要做到什么程度

| 选项 | 内容 | 成本 | 判断 |
| :--- | :--- | :--- | :--- |
| **A（推荐）** | 零计算版：保留现有数据，加上「去看本周规划」主行动 + 补看队列入口 + 顶部对齐收高 | 0.5 天 | 不动算法、不新增计算，纯导航与排版 |
| B | 决策版：空态里直接给出「本周最优一晚」（含场次预览） | 1.5 天 | 需在 tonight 视图跑背包 DP，**违背性能纪律**（`week` 现在只在 week 视图算）。除非接受额外 30–50ms |
| C | 只收敛高度（把 260px 收到 160px），不加行动 | 0.2 天 | 治标；仍是死路文案 |

> **推荐 A。** 空态的第一职责是"给出下一步"，不是"展示全部可能性"。B 的收益（多一个信息）不值一次算法重算。

### D2　赛前舞台怎么处理 3.4:1

| 选项 | 内容 | 成本 | 判断 |
| :--- | :--- | :--- | :--- |
| **A（推荐）** | 赛前态抬到 `max-h-[52vh] min-h-[280px]`，队徽内收，倒计时下方补一行「档位 · 指数 · 一句看点」 | 1 天 | 赛前态变成真正的舞台；赛中线路上限 `46vh` 不动，避免影响播放 |
| B | 保持 295px，明确降级为"信息条"：把队徽+倒计时横向压缩成一行，省下的 140px 给情报面板 | 0.5 天 | 情报更早进入视野，但"观赛大屏"的仪式感没了 |
| C | 赛前态直接 16:9（1014×570） | 0.3 天 | 会把情报面板挤出首屏，赛前态内容量撑不满 570px |

> **推荐 A。** 理由：这是唯一一个既解决"哑铃结构"又不牺牲情报可见性的方案。B 会让产品读起来像仪表盘而非看台。

### D3　灰阶从 4 档怎么办

实测：`secondary 12.4:1 → muted 7.29 → faint 6.37`，两级间隔 1.70 / **1.14**（极不均匀，最后一级感知不到）。

| 选项 | 内容 | 视觉后果 |
| :--- | :--- | :--- |
| **A（推荐）** | `--text-muted` `#94a0b2` → **`#a4afc0`**（faint 不动） | 三档间隔变成 1.54 / 1.37，近似等比；muted 在 press 上仍 6.40:1，安全 |
| B | 合并 faint 进 muted，灰阶降到 3 档 | 34 处 `text-faint` 全部变亮，密集列表（赛程页 81 处）会明显变吵 |
| C | 不动色值，只立规矩：faint 不得用于真实内容 | 0 视觉变化，0 解决；下一次还是会混用 |

> **推荐 A。** 一处 CSS 变量改动，全站生效，`text-faint` 的用法一行不用动。B 看似更"干净"，但代价是赛程页可读密度下降——那正是这个产品最强的地方。

## 二、第一批：P0（4 项，预计 0.5 天）

### P0-1　顶栏时钟断点降至 lg，日期与档位二级降级

- **定位**：`src/components/TopBar.jsx:109-119`
- **根因**：时钟容器写 `hidden ... xl:flex`。断点选在 1280，而 1280×800 扣掉窗口边框正好落在断点下方；且"消失"是唯一降级手段。
- **改法**：根容器 `hidden → lg:flex`；日期与"日间档"各自 `hidden xl:inline`，形成两级降级（lg 只显示 HH:MM）。

```jsx
// 改前
<div className="no-drag hidden shrink-0 items-center gap-2.5 xl:flex">
  <div className="flex items-center gap-2 rounded-full border border-line-hairline bg-surface-card px-3 py-1">
    <span className="h-1.5 w-1.5 rounded-full bg-accent/80" aria-hidden="true" />
    <span className="font-num text-xs font-semibold tabular-nums text-text-primary">{bjClock(now)}</span>
    <span className="font-num text-xs tabular-nums text-text-faint">{bjDate(now)}</span>
    <span className="border-l border-line-hairline pl-2 text-xs font-medium text-text-muted">{watchPeriodOf(now)}</span>
  </div>
</div>

// 改后
<div className="no-drag hidden shrink-0 items-center lg:flex">
  <div className="flex items-center gap-2 rounded-full border border-line-hairline bg-surface-card px-2.5 py-1 xl:px-3">
    <span className="h-1.5 w-1.5 rounded-full bg-accent/80" aria-hidden="true" />
    <span className="font-num text-xs font-semibold tabular-nums text-text-primary">{bjClock(now)}</span>
    <span className="hidden font-num text-xs tabular-nums text-text-faint xl:inline">{bjDate(now)}</span>
    <span className="hidden border-l border-line-hairline pl-2 text-xs font-medium text-text-muted xl:inline">
      {watchPeriodOf(now)}
    </span>
  </div>
</div>
```

- **宽度预算**：1024 下 左组(logo+4 tab≈460) + 时钟(lg 态≈100) + 右组(搜索+积分榜+球队+设置≈300) ≈ 860，余量 160px。
- **验收**：1120 视口顶栏可见 `HH:MM`；1280+ 显示完整胶囊；1024 顶栏无换行、Tab 未被挤掉文字。
- **风险**：低。若 1024 真溢出，右组"数据健康"在 <xl 已是图标态，无需额外处理。

### P0-2　周视图 7 个日格热区提到 24px

- **定位**：`src/components/WeekView.jsx:124-141`（`<button>` 的 className）；父容器 `WeekView.jsx:88` 的 `space-y-1`
- **根因**：`rowHeight = items.length ? lanes * 8 + 2 : 4`，空赛日只给 4px 车道 + `py-0.5`，按钮实测 `302×15`。
- **改法**：按钮加 `min-h-6`（24px，Tailwind 3.4 支持 spacing 刻度），`py-0.5 → py-1`；**车道高度逻辑完全不动**——空赛日仍是 4px 细线，只是被居中放进 24px 的行盒里。

```jsx
// 改前
className={`flex w-full items-center gap-1.5 rounded-md px-0.5 py-0.5 text-left transition-colors ...`}

// 改后
className={`flex w-full min-h-6 items-center gap-1.5 rounded-md px-0.5 py-1 text-left transition-colors ...`}
```

- **高度代价**：7 行合计约 166px → 192px（+26px）。左栏可滚动，且第三批 P1-1 会回收 100px 以上的空态留白，净空间为正。
- **为什么不改 `rowHeight`**：那条逻辑表达的设计意图是对的（"周一已过去不该和周六四场占同样高度"）。热区和视觉高度解耦，问题在热区不在视觉。
- **验收**：7 个日格 `getBoundingClientRect().height ≥ 24`；车道色块高度与改前一致；相邻行热区不重叠（`space-y-1` = 4px 间隔 > 0）。
- **风险**：低。

### P0-3　去掉三处 `-mr-1`，消除 4px 横向溢出

- **定位**：`TonightView.jsx:377`、`WeekView.jsx:736`、`PlayerStage.jsx:1467`
- **根因**：`-mr-1` + `pr-1` 组合是想让滚动条压在父级 padding 上，但父级 `section` 带 `overflow-hidden`，导致内容净宽 326 > 容器 322，右侧被裁 4px。macOS 覆盖式滚动条看不出来，Windows 传统滚动条会切掉行尾数值。
- **改法**：三处**只删 `-mr-1`，保留 `pr-1`**。

```jsx
// 改前
`scrollbar-thin -mr-1 min-h-0 flex-1 space-y-0.5 overflow-y-auto pr-1`
// 改后
`scrollbar-thin min-h-0 flex-1 space-y-0.5 overflow-y-auto pr-1`
```

- **视觉差异**：滚动条左移 4px，内容右边缘多 4px 留白。可接受，且比被裁切好。
- **验收**：三个容器的 `scrollWidth === clientWidth`；Windows 真机上列表行尾「指数」数值完整。
- **风险**：低。唯一副作用是滚动条与卡片右边界间距减少 4px，需在截图里确认不难看。

### P0-4　清除 3 处 10px 字号

- **定位**：`DramaMeter.jsx:44`、`DramaMeter.jsx:57`、`SeasonReportModal.jsx:359`
- **根因**：刻度标签（`0'` / `90'+` / 整点小时数）在窄容器里放不下，用 10px 硬塞——直接绕过自己写的 11px 下限。
- **改法**：全部 `text-[10px] → text-2xs`（11px）。若 DramaMeter 刻度放不下，**减刻度数量**而不是缩字号。

```jsx
// DramaMeter.jsx:44
<span className="font-num text-2xs text-text-faint">0&apos;</span>
// DramaMeter.jsx:57
<span className="font-num text-2xs text-text-faint">90&apos;+</span>
// SeasonReportModal.jsx:359
<span className="font-num text-2xs text-text-faint">{String(hr).padStart(2, '0')}</span>
```

- **验收**：`grep -rn "text-\[1[0-9]px\]" src/` 返回空。
- **风险**：极低。SeasonReportModal 是 24 根柱子，11px 两位数标签在 1/24 宽度下可能挤压——执行时先量，若挤压则改 `hours` 采样（每 3 小时一根标签）。

## 三、第二批：P1 几何与热区（5 项，预计 1.5 天）

### P1-3　顶栏改三列栅格，时钟真正居中

- **定位**：`TopBar.jsx:151`
- **根因**：`justify-between` 只在左右两组等宽时居中。实测时钟中心 761 vs 视口中心 720，偏 41px；整组偏 107px。
- **改法**：header 由 flex 改 grid 三列，左右各 `minmax(0,1fr)`，中间 `auto`。右组补 `justify-end`。

```jsx
// 改前
className="drag-region relative flex h-[52px] min-h-[52px] select-none items-center justify-between border-b border-line-hairline bg-surface-panel/95 px-3.5 xl:px-5 backdrop-blur-xl shadow-sm"

// 改后
className="drag-region relative grid h-[52px] min-h-[52px] select-none grid-cols-[minmax(0,1fr)_auto_minmax(0,1fr)] items-center border-b border-line-hairline bg-surface-panel/95 px-3.5 xl:px-5 backdrop-blur-xl shadow-sm"
```
右组容器（`TopBar.jsx:214`）追加 `justify-end`。

- **验收**：时钟组中心与 `innerWidth/2` 偏差 ≤ 2px（1440 / 1280 / 1120 三档）；左组在 1024 不被压缩换行（`minmax(0,1fr)` 允许收缩，需确认 Tab 未截断）。
- **风险**：中低。`minmax(0,1fr)` 会让左组可能被压缩——执行时在 1024 量一次，若 Tab 被截则左组外层加 `shrink-0`。

### P1-5　圆角阶梯从 7 档收到 5 档

- **定位**：`tailwind.config.js:41-51`
- **根因**：2/4/6/8/12/16/full 七档全在用，但 6px 与 8px 在 32–40px 高的元素上视觉差 2px，人眼不可分辨。35 个 6px 和 7 个 8px 混用传达的是"没有规则"。
- **改法**：**只改配置文件，JSX 一行不动**。把 4/6/8 三档映射到同一个值 8px：

```js
borderRadius: {
  none: '0',
  sm: '2px',        // 保留：赛果方块 / 微条柱
  DEFAULT: '8px',   // 4 → 8
  md: '8px',        // 6 → 8
  lg: '8px',        // 8 → 8
  xl: '12px',       // 卡片（不动）
  '2xl': '16px',    // 浮层（不动）
  '3xl': '24px',    // 视觉徽章（不动）
  full: '9999px'
}
```

- **结果**：同屏内容圆角从 7 种降到 5 种（2 / 8 / 12 / 16 / full），且语义变成"微件 / 内容 / 卡片 / 浮层 / 圆形"——每一档都能一眼分辨。
- **验收**：周视图圆角种类 ≤ 5；小标签（`rounded`，原 4px）在 20px 高元素上不显胶囊化；赛果方块（`rounded-sm` 2px）不变。
- **风险**：中。`rounded`（4px）用在 12 处小标签上，改 8px 后视觉略圆。若截图显示"标签变胖"，则把 `DEFAULT` 留在 6px、只合并 `md` → 8px（仍能从 7 档降到 6 档）。

### P1-6　三处系统性偏小的热区

#### (a) 「查看说明」16×16 → 24×24 热区，视觉不变

- **定位**：`atoms.jsx:545-552`
- **改法**：`h-4 w-4` → `h-6 w-6 -m-1`（外扩 4px 后用负边距回收布局占位，图标仍 13px）

```jsx
// 改前
className="inline-flex h-4 w-4 cursor-help items-center justify-center rounded-full ..."
// 改后
className="inline-flex h-6 w-6 -m-1 cursor-help items-center justify-center rounded-full ..."
```

- **验收**：所有 `aria-label="查看说明"` 元素 ≥ 24×24；行内文字基线不发生位移。

#### (b) 周视图「固定 / 换掉」36×17 → ≥ 24px 高

- **定位**：`WeekView.jsx:1092-1118`
- **改法**：两枚按钮 `px-1.5 py-0.5` → `px-2 py-1`（约 36×22），容器 `gap-1` → `gap-1.5`；`text-2xs` 保持。

```jsx
// 固定
className={`rounded border px-2 py-1 text-2xs leading-none transition-colors cursor-pointer ...`}
// 换掉
className="rounded border border-line-hairline px-2 py-1 text-2xs leading-none ..."
```
容器：`<div className="flex shrink-0 flex-col items-end justify-end gap-1.5">`

- **说明**：22px 仍未到 24px。如果要严格达 24，需把 `py-1` 改 `py-1.5`（→26px），右侧按钮列会变高，需确认行高不受挤压。**执行时按 26px 做**（`py-1.5`）。
- **验收**：两枚按钮高度 ≥ 24；两按钮垂直间隔 ≥ 6px；行高增加不影响左栏滚动。

#### (c) 额度滑杆 16px → 32px 拖拽带

- **定位**：`MeView.jsx:676-688`
- **改法**：`className="mt-2 w-full accent-resource"` → `className="mt-1 w-full py-2 accent-resource"`（原生 range 的整个盒子都是命中区，padding 直接扩大拖拽带；滑轨视觉不变）

- **验收**：`input[type=range]` 盒子高度 ≥ 32px；滑轨位置与刻度文字间距不变。
- **风险**：低。

### P1-7　折叠线路条归属舞台

- **定位**：`PlayerStage.jsx:1342-1400`（`railMode` 分支）
- **根因**：折叠态是 38×116 的图标竖条，浮在最右侧（距主内容 40px），控制的是舞台的线路，但视觉上与舞台无连接。
- **改法（默认，低风险）**：给竖条加 90° 竖排标签「线路」，并把 `gap-1.5` 提到 `gap-2` 以撑开可点间距。

```jsx
// railMode 分支容器追加竖排标签
<span className="mt-1 text-2xs tracking-widest text-text-faint" style={{ writingMode: 'vertical-rl' }}>
  线路
</span>
```

- **改法（可选，结构性）**：把 `railMode` 的渲染位置移到舞台卡片内部 `absolute right-2 top-2`（与「小窗/全屏」同组）。这需要把 rail 从 `#match-lines` 的兄弟位置移到 stage card 子节点，**会碰到 PlayerStage 的条件渲染结构**，建议单独一次提交、单独回归。
- **验收**：折叠态有可见文字标签；4 个图标可点区 ≥ 24×24；展开/收起仍走同一 state。
- **风险**：结构性方案为中；默认方案为低。

## 四、第三批：P1 设计决策 + P2 治理（10 项，预计 2 天）

### P1-1　无赛空态升级（按 D1-A 执行）

- **定位**：`TonightView.jsx:293`（`centeredEmpty`）、`382-395`（`EmptyState` 调用）；`App.jsx:1513-1526`（传参）
- **现状实测**：空态卡 260px 高（32px 图标 + 两行灰字），连同上下留白占左栏可视高度 60%，文案是死路。
- **改法**：三步，全部零算法计算。

**第一步：加一个纯导航回调（App.jsx）**

```jsx
<TonightView
  ...
  onOpenSettings={openSettings}
  onGoWeek={() => setView('week')}   // 新增：纯导航
  queueCount={pendingQueueCount}     // 新增：复用 App.jsx:1035 已算好的待补计数
/>
```

**第二步：TonightView 空态改版**

```jsx
{centeredEmpty ? (
  <div className="flex flex-1 flex-col items-start gap-3 rounded-xl border border-line-hairline bg-surface-card/60 p-4 text-left">
    <div className="flex items-center gap-2">
      <span className="flex h-8 w-8 items-center justify-center rounded-lg bg-surface-raised text-text-faint">
        <IconEmpty />
      </span>
      <div className="min-w-0">
        <p className="text-sm font-semibold text-text-primary">
          {hero ? '今晚仅此一场焦点战' : '今晚没有已排期的比赛'}
        </p>

    </div>

    <div className="flex w-full flex-col gap-2">
      <Button variant="accentSoft" size="sm" onClick={onGoWeek}>
        去看本周规划 · 挑一晚
      </Button>
      {queueCount > 0 && (
        <Button variant="ghost" size="sm" onClick={onOpenSettings}>
          明早补看 · {queueCount} 场待补

    </div>
  </div>

```

**第三步：`flex-1` 不再纵向居中**。容器去掉 `items-center justify-center`，改 `justify-start`，让空态从上往下排，回收约 100px 空白。

### 7.3 三处未达标与原因（不是遗漏，是约束）

1. **时钟居中 +30px，未到 ≤2px。** macOS 窗口为交通灯预留 80px 左侧内边距（`paddingLeft: isMacDesktop ? 80`），header 内容盒因此比视口左移 66px，居中参照点随之偏移。改为绝对居中会在 1120 下与左组 Tab 重叠（实测左组右缘 546px，视口中心 560px，余量仅 14px）。**结论：保留三列栅格（保证永不重叠），偏差从 107px 收到 30px 已是该约束下的最优解。**
2. **舞台 2.4:1，未到 1.6–2.2。** 1.6:1 需要约 69vh（570px），会把情报面板整体挤出首屏；2.4:1 是在「情报面板顶部 ≤60% 屏高」这条硬约束下能取到的最大值。1120 视口另用 `max-h-[38vh]`，避免堆叠布局下情报被推到 81% 处。
3. **11px 文本占比未降（37/60/47/47%）。** 这是原方案自身的目标冲突：P0-4 把 3 处 10px 提到 11px，必然抬高 11px 占比。真正该改的不是字号数值，而是**让 11px 只承担元信息**（现在它也承担了正文），属于内容层级问题，不在本次范围。

### 7.4 一处执行中撤回的改动

**P2-4（近5场色块 16→20px）已回滚。** 实测 5 枚 20px 色块 + 4×2px 间距 = 108px，超出情报面板该列 100px 的可用宽度，导致行内溢出 4px；16px 是这一列的物理上限。原判断「11px 汉字在 16px 方块里糊成色块」来自 0.75 缩放的验收截图，**100% 缩放下可读**。已在《UI 审查报告》对应条目回注更正。
